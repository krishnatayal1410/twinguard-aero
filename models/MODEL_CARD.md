# TwinGuard Aero — Model Card

## Purpose

The packaged models support a **synthetic proof-of-concept** for SIH26054. They demonstrate how anomaly detection, fault classification and Remaining Useful Life (RUL) estimation can plug into the hybrid Digital Twin pipeline.

They are **not validated aero-engine safety models** and must not be used for flight release, maintenance certification or autonomous safety-critical decisions.

## Current runtime contract

- Feature schema: `aero-piston-v2`
- Target asset: generic aero-piston engine demonstrator
- Fault taxonomy:
  - normal
  - lubrication degradation
  - overheating
  - cooling degradation
  - abnormal vibration
  - sensor drift
  - injector abnormality
  - misfire
  - combustion instability
  - alternator degradation

The runtime compares `models/feature_order.json` and `models/fault_labels.json` with the current code before loading packaged ML artifacts. Incompatible/stale artifacts are rejected and TwinGuard falls back to transparent engineering logic.

## Training data

`ai/train_models.py` generates operating-condition-dependent synthetic telemetry and residuals from a low-order generic aero-piston surrogate. Faults are injected synthetically.

This is useful for:
- integration testing,
- controlled fault demonstrations,
- UI/mission-flow development,
- checking qualitative directionality.

It is not evidence of field accuracy.

## Models

- Isolation Forest: novelty/anomaly detection against synthetic healthy behavior.
- XGBoost classifier: synthetic fault-class prediction.
- XGBoost regressor: synthetic RUL estimate.
- Engineering fallback: transparent residual/rule-based diagnostic and RUL surrogate used when native ML is disabled or incompatible.

## RUL limitation

Synthetic RUL targets are generated by the proof-of-concept degradation generator. They are not engine-specific run-to-failure ground truth. The UI therefore labels the output **simulation-derived RUL**.

## Validation required before operational use

A real deployment would require, at minimum:
- authorized engine/test-rig telemetry,
- calibrated performance maps or engine-specific physics,
- known fault/degradation cases,
- run-to-failure or maintenance-event ground truth,
- uncertainty calibration,
- out-of-distribution testing,
- false-alarm and missed-detection analysis,
- environmental/mission-envelope validation,
- cybersecurity and safety assurance appropriate to the deployment context.

## Reporting rule

Any metric in `synthetic_metrics.json` must be described as a **synthetic proof-of-concept metric**. It must never be presented as validated real MALE-UAV engine performance.
